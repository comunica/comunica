Most important issues

Ordered by impact on these queries. Red marks issues that silently change the answer or stop the query. None are fixed yet; the hand-off notes with code locations are in performance/nde-federated/PERFORMANCE-ISSUES.md.

Correctness

  1. Redirected service-description fetch replaces the endpoint URL

    Q1 to Q6 needed a harness workaround

    A GET on sparql.ldmax.nl/<id> redirects to a web landing page, and Gouda redirects to its /matgui/ UI. Comunica then sends every query to the redirect target, even for sources typed sparql. That breaks about 60 museum endpoints in the register and the Gouda one.

    Outlook A Comunica bug: these endpoints publish no service description, so no wrong sd:endpoint is involved. The 404 fallback to urlBackup cannot fire, because the backup is already the redirected URL, and Gouda answers 200 with HTML anyway.

  2. Silently truncated endpoint results are taken as complete

    Q1: 3.6% of the answer

    TriplyDB (RKD, Muziekweb, RCE) returns at most 10,000 rows, even with an explicit LIMIT 15000, and sends no signal. Q1 starts from 87,383 RKD artists, gets 10,000, and ends with 12 of ~334 answers.

    Outlook Detectable and fixable: COUNTs are often exact, a result that stops at exactly 10,000 is a strong hint, and OFFSET 10000 LIMIT 1 confirms it in one request. OFFSET paging works on these endpoints.

  3. Joins through blank nodes are dropped

    Q7: 1 of 11, Q5b: 0 of 536 items

    The bind-source join skips bindings whose join value is a blank node. 97% of the register's dataset distributions and all Beeld en Geluid creator roles are blank nodes.

    Outlook Solvable: every lost result is a join inside one source. Evaluate the patterns connected through the blank node as one subquery at the source that produced it, bound on an IRI (here the dataset).

  4. ?query= is appended to endpoint URLs that already have a query string

    Turned issue 1 into a 404 for ldmax

    fetch-sparql-endpoint builds ${endpoint}?query=, producing URLs like query?slug=Q1820897?query=SELECT….

    Outlook Small upstream fix: use & when the URL already contains ?.

Query plans across many sources

  1. OPTIONAL is evaluated one binding at a time, with a COUNT per binding

    Q4: 100,401 requests, timeout

    For OPTIONAL { ?object schema:dateCreated ?date } over 35 sources, Comunica sent 47,516 COUNT and 50,919 SELECT requests, one pair per object per source. Q6 (OPTIONAL property path) returned nothing in 10 minutes.

    Outlook Use the block-based optional bind join over multiple sources, and skip COUNTs for bound operations inside bind joins.

  2. Full unbound scans are chosen over bind joins

    Q4b: 411 MB, timeout

    After a UNION, ?object schema:name ?title was fetched unbound from all 34 museums (411 MB, about 3M rows) for about 2,000 answers. Q6 fetched the last property-path step ?x skos:prefLabel ?style unbound from every source.

    Outlook The same plan finishes in 11 s over 6 sources, so the cost model needs to weigh "one scan per source, times many sources".

  3. Bound variables are not pushed into UNION branches

    Q5: failed

    A 1-row anchor (?gtaa) joined with a 3-branch UNION ran every branch unbound, including a scan of Muziekweb that hit the 10k cap. Repeating the anchor inside each branch: 9 s and 121 requests instead of a failure after 11,589.

    Outlook Plan-dependent: Q3 has the same shape and did get the binding pushed.

  4. Bind-join blocks go to every source, with no IRI namespace pruning

    Q1: 8,800 of 12,036 requests

    Blocks of RKD artist IRIs and museum-specific n2t.net/ark:/<NAAN> IRIs were sent to all 22 sources, although each namespace occurs in one source.

    Outlook Prefix or authority summaries (HiBISCuS style, or the VoID linksets the NDE Dataset Knowledge Graph already publishes) would prune most of these.

Load and robustness

  1. No limit on concurrent HTTP requests

    Q1 peak: 4,183 in flight

    Up to 4,183 requests were in flight at once. About 60 ldmax endpoints share one host. p50 latency rose to 11 s for queries that take about 150 ms alone.

    Outlook A per-host concurrency limit would also prevent most of the 429/503 responses below.

  2. Rate limits switch planning modes, and retries are off by default

    Q6 fails without retries

    Genealogy Online (429) and RCE (503) rejected the initial COUNT burst, which turned COUNTs off for those endpoints for an hour. Without retries, one 503 on a data request aborts the whole query.

    Outlook Retry 429/503 with Retry-After by default for SPARQL sources, and do not treat rate limiting as "COUNT too slow".

  3. Overlapping sources multiply results and identical requests

    Q3: 107 of 251 requests repeated

    WO2Net carries a copy of the NIOD thesaurus and the Dataset Knowledge Graph copies the register. Without DISTINCT, Q2 returns every row 4 times.

    Outlook Deduplicate identical in-flight requests per endpoint.

Smaller items: one service-description GET per source even for sources typed sparql; COUNT queries are not batched per source the way ASK queries now are; and at large result volumes the streaming SPARQL JSON parser plus garbage collection dominate CPU.

The queries

Join axes come from the VoID linksets in the NDE Dataset Knowledge Graph, checked against the exact URI forms in each endpoint. Each source list also holds related endpoints without matching data, to test source selection.

Q1

Works by women artists in Dutch museum collections

Use case
Museums link their creator records to RKDartists with schema:sameAs, and RKD records gender and birth dates. The query lists works by female artists with their RKD birth date.
Result
12 rows for 2 artists (Charley Toorop, Lizzy Ansingh). The correct answer has about 334 rows for 28 artists in 6 museums: Groninger Museum 286, Musiom 22, Jan Menze van Diepen 15, Gerrit van Houten 8, DKOR 2, Kranenburgh 1.
What the plan did
Starts from the 87,383 female RKD artists, of which TriplyDB returns 10,000. It then sends those in blocks to all 22 sources for schema:sameAs (8,800 requests) and schema:creator (3,014 requests). The ASK mode of the branch produced the same plan.
Sample rows
  • Toorop, Charley · 1891-03-24 · Zelfportret met Edgar en John
  • Ansingh, Lizzy · 1875-03-13 · Christine Jacoba Tjarda van Starkenborgh Stachouwer - Quintus
Query (q1-women-artists.rq)
# Works by women artists in Dutch museum collections, with life data from RKD.
# Museums link their local creator records to RKDartists with schema:sameAs;
# RKD records gender (AAT 300189557 = female) and birth dates.
PREFIX schema: <https://schema.org/>
PREFIX crm: <http://www.cidoc-crm.org/cidoc-crm/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
SELECT ?artist ?name ?birth ?work ?title WHERE {
  ?work schema:creator ?agent .
  ?agent schema:sameAs ?artist .
  ?artist crm:P2_has_type <http://vocab.getty.edu/aat/300189557> ;
          rdfs:label ?name .
  ?work schema:name ?title .
  OPTIONAL { ?artist crm:P98i_was_born/crm:P4_has_time-span/crm:P82a_begin_of_the_begin ?birth }
}

Q2

Victims who died in Kamp Vught, with their birthplace

Use case
Genealogy Online links each victim's death place to the NIOD WO2 thesaurus, and the victim to an Oorlogslevens person record in WO2Net. That record links the birthplace to the thesaurus, which provides its label: three hops across three endpoints.
Result
53 rows, exactly the ground truth. Without DISTINCT, 212 rows: WO2Net also holds a copy of the thesaurus, so both labels match twice.
What the plan did
Six museum endpoints receive every block of victim IRIs although none of them contain those IRIs.
Sample rows
  • Joseph Wilhelmus Toussaint · 1945-05-21 · Nijmegen
  • Gerrit GOLDENBELD · 1944-12-09 · Deventer
Query (q2-vught-victims.rq)
# Victims who died in Kamp Vught (Genealogy Online), with their birthplace as recorded
# in the Oorlogslevens person records of WO2Net, labelled via the NIOD WO2 thesaurus.
PREFIX schema: <https://schema.org/>
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
SELECT DISTINCT ?victim ?name ?deathDate ?birthPlace WHERE {
  ?camp skos:prefLabel "Kamp Vught"@nl .
  ?victim schema:deathPlace ?camp ;
          schema:name ?name ;
          schema:deathDate ?deathDate ;
          schema:sameAs ?warLife .
  ?warLife schema:birthPlace ?bp .
  ?bp skos:prefLabel ?birthPlace .
  FILTER(LANG(?birthPlace) = "nl")
}

Q3

Collection objects about Kamp Vught

Use case
WO2Net links objects to the thesaurus directly, and museums link a local term with schema:sameAs. A UNION covers both.
Result
205 rows, exactly the ground truth, from WO2Net and Nationaal Monument Kamp Vught.
What the plan did
107 of the 251 query requests were identical repeats, caused by the duplicated thesaurus.
Sample rows
  • Reçu van pakketje verzonden aan Cees van den Bergh
  • Coba Laetemia-Tahitu vertelt over de aankomst in Rotterdam (interview segment)
Query (q3-camp-objects.rq)
# Collection objects about Kamp Vught in Dutch WWII collections,
# either linked directly (WO2Net) or via a local term mapped to the WO2 thesaurus (museums).
PREFIX schema: <https://schema.org/>
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
SELECT DISTINCT ?object ?title WHERE {
  ?camp skos:prefLabel "Kamp Vught"@nl .
  { ?object schema:about ?camp . }
  UNION
  { ?object schema:about ?term . ?term schema:sameAs ?camp . }
  ?object schema:name ?title .
}

Q4 and Q4b

Portraits across museums via CHT and AAT

Use case
Terminology-aware search. Museums map their local object types to CHT or to the equivalent AAT concept, and CHT links the two with skos:exactMatch. The query finds portraits regardless of which mapping a museum used.
Result
Neither run finishes. The ground truth is 2,022 objects in 5 museums. Over a subset of 6 sources, Q4b finishes in 11.3 s with 1,957 results.
What the plan did
Q4: the OPTIONAL date costs a COUNT plus a SELECT per object per source, 100,401 requests in 15 minutes. Q4b: schema:name is downloaded from all 34 museums (411 MB), after which the process stays CPU-bound in JSON parsing and garbage collection.
Sample rows
  • Portret van Cornelis van Groenendijck (1658-1704) · 1668
  • Prent; reproductie; portret (foto) van Geert Reinders
Query (q4-portraits.rq)
# Portraits in Dutch museum collections, found through the CHT concept "portretten":
# museums map their local object-type terms either to CHT itself or to the equivalent AAT concept.
PREFIX schema: <https://schema.org/>
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
SELECT ?object ?title ?date WHERE {
  ?cht skos:prefLabel "portretten"@nl ;
       skos:exactMatch ?aat .
  { ?term schema:sameAs ?aat . } UNION { ?term schema:sameAs ?cht . }
  ?object schema:artform ?term ;
          schema:name ?title .
  OPTIONAL { ?object schema:dateCreated ?date }
}
Variant query (q4b-portraits-noopt.rq)
# Portraits in Dutch museum collections, found through the CHT concept "portretten":
# museums map their local object-type terms either to CHT itself or to the equivalent AAT concept.
# Variant without the OPTIONAL creation date.
PREFIX schema: <https://schema.org/>
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
SELECT DISTINCT ?object ?title WHERE {
  ?cht skos:prefLabel "portretten"@nl ;
       skos:exactMatch ?aat .
  { ?term schema:sameAs ?aat . } UNION { ?term schema:sameAs ?cht . }
  ?object schema:artform ?term ;
          schema:name ?title .
}

Q5 and Q5b

Louis Andriessen across Dutch music and broadcast heritage

Use case
A person profile from one GTAA identifier: compositions in Muziekschatten, albums in Muziekweb, and broadcast items in the Beeld en Geluid catalogue.
Result
Q5 fails. Q5b finds all 131 compositions and all 44 albums, but 0 of the 536 broadcast items.
What the plan did
Q5: the GTAA binding is not pushed into the UNION branches, so they run as full scans, and the query dies on a network error after 11,589 requests. Q5b repeats the anchor in each branch. Its broadcast branch is lost because all creator roles in the catalogue are blank nodes.
Sample rows
  • album · Doctor nero
  • composition · Bassoon blue
Query (q5-andriessen.rq)
# Composer Louis Andriessen across Dutch music and broadcast heritage:
# compositions (Muziekschatten), albums (Muziekweb) and broadcast items (Beeld en Geluid),
# all reached through his GTAA person identifier.
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
PREFIX owl: <http://www.w3.org/2002/07/owl#>
PREFIX schema: <http://schema.org/>
PREFIX sdo: <https://schema.org/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX mw: <https://data.muziekweb.nl/vocab/>
SELECT ?kind ?item ?title WHERE {
  ?gtaa skos:prefLabel "Andriessen, Louis"@nl ;
        skos:inScheme <http://data.beeldengeluid.nl/gtaa/Persoonsnamen> .
  {
    ?person owl:sameAs ?gtaa .
    ?item schema:composer ?person ;
          schema:name ?title .
    BIND("composition (Muziekschatten)" AS ?kind)
  } UNION {
    ?person owl:sameAs ?gtaa , ?mwPerson .
    ?mwPerson mw:album ?item .
    ?item rdfs:label ?title .
    BIND("album (Muziekweb)" AS ?kind)
  } UNION {
    ?role sdo:creator ?gtaa .
    ?item sdo:creator ?role ;
          sdo:name ?title .
    BIND("broadcast item (Beeld en Geluid)" AS ?kind)
  }
}
Variant query (q5b-andriessen-anchored.rq)
# Composer Louis Andriessen across Dutch music and broadcast heritage:
# compositions (Muziekschatten), albums (Muziekweb) and broadcast items (Beeld en Geluid),

  {
    ?gtaa skos:prefLabel "Andriessen, Louis"@nl .

          schema:name ?title .

  } UNION {
    ?gtaa skos:prefLabel "Andriessen, Louis"@nl .

    ?mwPerson mw:album ?item .
    ?item rdfs:label ?title .
    BIND("album (Muziekweb)" AS ?kind)
  } UNION {
    ?gtaa skos:prefLabel "Andriessen, Louis"@nl .
    ?role sdo:creator ?gtaa .
    ?item sdo:creator ?role ;
          sdo:name ?title .
    BIND("broadcast item (Beeld en Geluid)" AS ?kind)
  }
}

Q6 and Q6b

National monuments in Gouda with RCE style and original function

Use case
The Gouda Tijdmachine links its building records to the RCE monument register with rdfs:seeAlso, and RCE provides the structured style and original function.
Result
Q6 returns nothing in 10 minutes. Q6b (style required) returns exactly the ground truth: 73 distinct value rows (282 rows at RDF term level, because labels come in several languages and datatypes).
What the plan did
Q6 runs the optional property path per binding, with its last step as an unbound scan of skos:prefLabel in every source (26 MB from CHT, 72 MB from RCE).
Sample rows
  • Kantoorgebouw, Kaaspakhuis, Wachtelstraat 52 · Zakelijk Expressionisme · Kaaspakhuis
Query (q6-gouda-monuments.rq)
# National monuments (rijksmonumenten) in Gouda: buildings of the Gouda Time Machine
# joined with the RCE monument register for their style and original function.
PREFIX schema: <https://schema.org/>
PREFIX ceo: <https://linkeddata.cultureelerfgoed.nl/def/ceo#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX gtm: <https://www.goudatijdmachine.nl/def#>
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
SELECT ?building ?name ?monumentNumber ?style ?originalFunction WHERE {
  ?building a gtm:Gebouw ;
            schema:name ?name ;
            rdfs:seeAlso ?monument .
  ?monument ceo:rijksmonumentnummer ?monumentNumber ;
            ceo:heeftOorspronkelijkeFunctie/ceo:heeftFunctieNaam/skos:prefLabel ?originalFunction .
  OPTIONAL { ?monument ceo:heeftStijlEnCultuur/ceo:heeftStijlEnCultuurNaam/skos:prefLabel ?style . }
}
Variant query (q6b-gouda-monuments-noopt.rq)
# National monuments (rijksmonumenten) in Gouda: buildings of the Gouda Time Machine
# joined with the RCE monument register for their style and original function (variant: style required).
PREFIX schema: <https://schema.org/>
PREFIX ceo: <https://linkeddata.cultureelerfgoed.nl/def/ceo#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX gtm: <https://www.goudatijdmachine.nl/def#>
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
SELECT DISTINCT ?building ?name ?monumentNumber ?style ?originalFunction WHERE {

Q7

Which datasets link to the WO2 thesaurus, and where can they be queried?

Use case
Discovery: joins the linksets in the NDE Dataset Knowledge Graph with the register's dataset descriptions and SPARQL distributions.
Result
1 row (the Dataset Knowledge Graph itself). The ground truth has 11 datasets, including WO2Net, Genealogy Online, Kamp Vught and Anne Frank House.
What the plan did
The register's distributions are blank nodes, so the join from dataset to distribution to endpoint is dropped. Without DISTINCT, 128 rows for 2 answers, because the Dataset Knowledge Graph copies the register.
Sample rows
  • Dataset Knowledge Graph · Dutch Digital Heritage Network · 1241 links
Query (q7-discovery.rq)
# Discovery: which datasets in the NDE register link to the NIOD WO2 thesaurus, how many links
# do they have (NDE Dataset Knowledge Graph linksets), and where can they be queried (register distributions)?
PREFIX void: <http://rdfs.org/ns/void#>
PREFIX dcat: <http://www.w3.org/ns/dcat#>
PREFIX dct: <http://purl.org/dc/terms/>
PREFIX foaf: <http://xmlns.com/foaf/0.1/>
SELECT DISTINCT ?dataset ?title ?publisher ?links ?endpoint WHERE {
  ?linkset void:objectsTarget <https://data.niod.nl/WO2_Thesaurus> ;
           void:subjectsTarget ?dataset ;
           void:triples ?links .
  ?dataset dct:title ?title ;
           dct:publisher/foaf:name ?publisher ;
           dcat:distribution ?distribution .
  ?distribution dct:conformsTo <https://www.w3.org/TR/sparql11-protocol/> ;
                dcat:accessURL ?endpoint .
  FILTER(LANG(?title) = "en" || LANG(?title) = "")
  FILTER(LANG(?publisher) = "en" || LANG(?publisher) = "")
}

How this was measured

  • A harness runs each query in a fresh Node process with the default engine of engines/query-sparql. A wrapped fetch records every request: kind (service description, ASK, COUNT, data), status, rows and bytes.
  • All sources were passed as { type: 'sparql', value: url }. Service-description GETs did not follow redirects (issue 1). Retries on 429/503 (httpRetryCount: 3) were on for all runs except Q1, which received no 429/503 responses.
  • The register lists 124 SPARQL distribution URLs. 112 are real endpoint URLs, and 97 of those answered a probe query.
  • Ground truth: each endpoint was queried directly, with every join that stays inside one endpoint pushed down to it.
  • Each figure is one run. I kept repeats to a minimum, because several of these queries put real load on public endpoints.
